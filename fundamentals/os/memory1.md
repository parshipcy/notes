# Memory Management Techniques

## Contiguous Memory Allocation

### 1. Why Do We Need Memory Management?

In a multiprogramming environment, multiple processes are kept in main memory (RAM) simultaneously.

Why?

- To keep CPU utilization high.
- To allow multiple processes to execute efficiently.
- To make the computer responsive.

Example: Suppose three processes are running:

```
             MAIN MEMORY (RAM)
        +-----------------------+
        |     Operating System  |
        +-----------------------+
        |       Process P1      |
        +-----------------------+
        |       Process P2      |
        +-----------------------+
        |       Process P3      |
        +-----------------------+
        |       Free Memory     |
        +-----------------------+
```

The OS must manage memory and ensure that processes do not interfere with each other.

### 2. Logical Address vs Physical Address

Logical Address (Virtual Address)

- Generated by the CPU.
- Used by a process to access instructions and data.
- Does not represent an actual physical RAM location.
- Range: `0 to max`.

Example: A process generates logical address `356`.

Physical Address

- Actual location in RAM.
- Calculated by the Memory Management Unit (MMU).
- A process cannot directly access its physical address.
- Range: `(R + 0) to (R + max)`, where R is the base address.

Example: If base address = 14000:

```
Physical Address = Base Address + Logical Address
                 = 14000 + 356
                 = 14356
```

Diagram: Address Translation

```
          CPU
           |
           | Logical Address
           |      356
           v
    +------------------+
    |       MMU        |
    |                  |
    | Base = 14000     |
    |                  |
    | 14000 + 356      |
    +------------------+
           |
           | Physical Address
           |      14356
           v
      +----------+
      |   RAM    |
      +----------+
```

Remember:

- Logical address = CPU-generated address.
- Physical address = Actual RAM address.
- MMU = Converts logical address into physical address.

### 3. MMU (Memory Management Unit)

MMU is a hardware component responsible for runtime mapping of logical addresses to physical addresses.

Formula:

```
Physical Address = Base Address + Logical Address
```

Example:

```
Base Address      = 5000
Logical Address   = 200

Physical Address  = 5000 + 200
                  = 5200
```

### 4. Memory Mapping and Protection

Question: How does the OS protect one process from accessing another process's memory?

The OS uses two registers:

1\. Relocation Register (Base Register)

- Stores the starting physical address of a process.
- Used to calculate the physical address.

2\. Limit Register

- Stores the maximum valid range of logical addresses.
- Checks whether the logical address is legal.

Example:

```
Relocation Register = 100040
Limit Register      = 74600
Logical Address     = 500
```

Check:

```
500 < 74600  → VALID

Physical Address = 100040 + 500
                 = 100540
```

If logical address = 80000:

```
80000 >= 74600 → INVALID

Result: Trap (Addressing Error)
```

Address Translation Diagram

```
             CPU
              |
              | Logical Address
              v
       +--------------+
       | Limit Check  |
       |              |
       | LA < Limit?  |
       +--------------+
          /       \
        YES        NO
         |          |
         v          v
    +---------+   TRAP
    |   MMU   |   Addressing
    |         |   Error
    | Base+LA |
    +---------+
         |
         v
   Physical Address
         |
         v
       MAIN RAM
```

Important points:

- Every logical address is checked against the limit register.
- During a context switch, the dispatcher loads the correct relocation and limit register values.
- Accessing OS memory or another process's protected memory causes a trap.
- This provides memory protection and process isolation.

### 5. Allocation Methods in Physical Memory

There are two allocation methods:

```
       Memory Allocation
              |
       +------+------+
       |             |
       v             v
  Contiguous     Non-contiguous
  Allocation     Allocation
```

**Contiguous Allocation:** Each process occupies one continuous block of memory.

**Non-contiguous Allocation:** A process can be stored in multiple separate memory blocks.

### 6. Contiguous Memory Allocation

In this technique, each process is stored in a single continuous block of physical memory.

There are two types:

```
      Contiguous Allocation
               |
        +------+------+
        |             |
        v             v
      Fixed        Dynamic
   Partitioning   Partitioning
```

### 6.1 Fixed Partitioning

In fixed partitioning, main memory is divided into partitions of fixed sizes before processes are loaded.

Partitions can be of equal or different sizes.

Example:

Suppose RAM has four partitions of 4 MB each.

```
       MAIN MEMORY
    +------------------+
    |   Operating OS   |
    +------------------+
    | P1 (3 MB)        |  1 MB Wasted
    +------------------+
    | P2 (3 MB)        |  1 MB Wasted
    +------------------+
    | P3 (3 MB)        |  1 MB Wasted
    +------------------+
    | P4 (3 MB)        |  1 MB Wasted
    +------------------+
```

Each process gets one partition, even if it does not use the entire partition.

Limitations of Fixed Partitioning:

1. Internal Fragmentation: When a process is smaller than its allocated partition, the remaining space is wasted.

Example:

```
Partition Size = 4 MB
Process Size   = 3 MB

+------------------+
| Process (3 MB)   |
+------------------+
| Wasted (1 MB)    |
+------------------+

Internal Fragmentation = 1 MB
```

2. External Fragmentation: Free memory exists in different locations, but it cannot be used because the required contiguous space is unavailable.

Example:

```
+------------------+
| P1               |
+------------------+
| Free (1 MB)      |
+------------------+
| P2               |
+------------------+
| Free (1 MB)      |
+------------------+
| P3               |
+------------------+
| Free (1 MB)      |
+------------------+
```

Total free memory = 3 MB.

But a process requiring 3 MB cannot be loaded into any single 1 MB partition.

3. Limitation on Process Size: A process cannot be loaded if its size is larger than the largest available partition.

Example:

```
Largest Partition = 4 MB
Process Size      = 5 MB

Result: Cannot load.
```

4. Low Degree of Multiprogramming: The number of processes is limited by the number of fixed partitions. Partition sizes cannot be adjusted according to process sizes.

### 6.2 Dynamic Partitioning

In dynamic partitioning, partition sizes are not decided in advance.

The OS creates partitions dynamically according to the size of incoming processes.

Example:

```
Process P1 = 5 MB
Process P2 = 2 MB
Process P3 = 3 MB
Process P4 = 4 MB
```

Memory allocation:

```
       MAIN MEMORY
    +------------------+
    | Operating System |
    +------------------+
    | P1 (5 MB)        |
    +------------------+
    | P2 (2 MB)        |
    +------------------+
    | P3 (3 MB)        |
    +------------------+
    | P4 (4 MB)        |
    +------------------+
```

Each process receives a partition matching its size.

Advantages over Fixed Partitioning

1. No internal fragmentation (in the basic model).
2. No fixed maximum partition size.
3. Better degree of multiprogramming.

**Limitation: External Fragmentation**

When processes complete, free memory blocks can appear between allocated processes.

Example:

```
       MAIN MEMORY
    +------------------+
    | Operating System |
    +------------------+
    | Free (5 MB)      |
    +------------------+
    | P2 (2 MB)        |
    +------------------+
    | Free (3 MB)      |
    +------------------+
    | P4 (4 MB)        |
    +------------------+
```

Total free memory = 8 MB.

Suppose P5 requires 8 MB.

```
Available: 5 MB + 3 MB = 8 MB
Required:  8 MB continuous

Result: Cannot load P5.
```

This is external fragmentation.
