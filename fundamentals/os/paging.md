# Paging: Non-Contiguous Memory Allocation

## 1. Why Do We Need Paging?

In the previous notes, we studied Dynamic Partitioning.

Its major disadvantage is External Fragmentation.

Let's understand the problem.

Suppose RAM has two free memory blocks:

```
       MAIN MEMORY
    +----------------+
    |      P1        |
    +----------------+
    |   Free 1 KB    |
    +----------------+
    |      P2        |
    +----------------+
    |   Free 1 KB    |
    +----------------+
```

Total free memory = 2 KB.

Now, suppose a new process P3 requires 2 KB.

Can we allocate it?

No!

Because the process requires 2 KB of continuous memory, but we have two separate blocks of 1 KB each.

This is called External Fragmentation.

### Solution: Paging

What if we divide the process into two blocks of 1 KB each?

```
Process P3 (2 KB)

+-------------+
|  Block 1 KB |
+-------------+
|  Block 1 KB |
+-------------+
```

Now, we can place these blocks in two different free memory locations.

This is the basic idea behind Paging.

## 2. What is Paging?

Paging is a memory-management technique that allows a process to be stored in non-contiguous locations in physical memory.

Instead of storing the entire process in one continuous block, we divide it into smaller fixed-sized blocks.

There are two important terms:

1\. Page

- Logical memory is divided into fixed-sized blocks called Pages.
- Pages belong to a process.

2\. Frame

- Physical memory (RAM) is divided into fixed-sized blocks called Frames.
- Frames hold pages of processes.



Important

&#x20;Page size = Frame size.



### Diagram

```
        LOGICAL MEMORY
          (Process P1)
       +---------------+
       |    Page 0     |
       +---------------+
       |    Page 1     |
       +---------------+
       |    Page 2     |
       +---------------+
       |    Page 3     |
       +---------------+

               |
               | Paging
               v

        PHYSICAL MEMORY
              (RAM)
       +---------------+
       |    Frame 0    |
       +---------------+
       |    Frame 1    |
       +---------------+
       |    Frame 2    |
       +---------------+
       |    Frame 3    |
       +---------------+
       |    Frame 4    |
       +---------------+
       |    Frame 5    |
       +---------------+
       |    Frame 6    |
       +---------------+
       |    Frame 7    |
       +---------------+
```

Pages of a process can be placed in any available frames.

For example:

```
Page 0  → Frame 3
Page 1  → Frame 7
Page 2  → Frame 5
Page 3  → Frame 2
```

Pages do not need to occupy consecutive frames.

### Important Points

1. Paging allows non-contiguous memory allocation.
2. It avoids external fragmentation.
3. It eliminates the need for compaction.
4. Page size and frame size are equal.
5. Page size is generally determined by processor architecture.
6. Traditionally, a common page size is 4096 bytes (4 KB), although modern processors can support multiple page sizes.

## 3. Page Table

Question: If pages are stored in different frames, how does the OS know where each page is located?

Answer: Using a Page Table.

A Page Table is a data structure that stores the mapping between logical pages and physical frames.

It tells us which physical frame contains a particular logical page.

### Example

Suppose we have the following page table:

| Logical Page | Physical Frame |
| ------------ | -------------- |
| Page 0       | Frame 3        |
| Page 1       | Frame 7        |
| Page 2       | Frame 5        |
| Page 3       | Frame 2        |

Diagram:

```
   LOGICAL MEMORY             PAGE TABLE

   +----------+              +-----------+
   | Page 0   | ------------>| Frame 3   |
   +----------+              +-----------+
   | Page 1   | ------------>| Frame 7   |
   +----------+              +-----------+
   | Page 2   | ------------>| Frame 5   |
   +----------+              +-----------+
   | Page 3   | ------------>| Frame 2   |
   +----------+              +-----------+
```

The page table helps translate a logical address into a physical address.

### Where is the Page Table Stored?

- The page table is stored in main memory (RAM).
- Its base address is stored in the Process Control Block (PCB).
- The system has a special register called Page Table Base Register (PTBR).
- PTBR points to the currently active page table.

During a context switch, changing the page table requires updating the PTBR.

## 4. Logical Address Structure in Paging

Every logical address generated by the CPU is divided into two parts:

```
       LOGICAL ADDRESS
       +-------------+
       |             |
       |  p    |  d  |
       |       |     |
       +-------------+

       p = Page Number
       d = Page Offset
```

1\. Page Number (p)

- Identifies the logical page.
- Used as an index in the page table.
- Helps find the corresponding physical frame.

2\. Page Offset (d)

- Identifies the exact location inside a page.
- Remains unchanged during address translation.

### Example

Suppose:

- Logical address space = 64 bytes.
- Page size = 16 bytes.

Number of pages:

64 / 16 = 4 pages

Since there are 4 pages, we need 2 bits for the page number.

Number of offset bits:

log_2(16) = 4 bits

Therefore:

```
Logical Address = 6 bits

+------------------+------------------+
| Page Number (2)  | Offset (4 bits)  |
+------------------+------------------+
```

Total bits = 2 + 4 = 6 bits.

## 5. Address Translation in Paging

Let's understand how a logical address is converted into a physical address.

Steps:

1. CPU generates a logical address.
2. Divide the logical address into Page Number (p) and Offset (d).
3. Use the page number as an index in the page table.
4. Find the corresponding physical frame number.
5. Combine the frame number with the original offset.
6. Generate the physical address.

### Example: Step-by-step

Consider the following:

| Parameter             | Value     |
| --------------------- | --------- |
| Logical address space | 64 bytes  |
| Physical memory       | 128 bytes |
| Page size             | 16 bytes  |
| Frame size            | 16 bytes  |
| Number of pages       | 4         |
| Number of frames      | 8         |

Page table:

| Page Number | Frame Number |
| ----------- | ------------ |
| 0           | 3            |
| 1           | 7            |
| 2           | 5            |
| 3           | 2            |

Suppose CPU generates logical address 25.

Step 1: Convert logical address into binary.

25 = 011001

We know:

- Page number = 2 bits.
- Offset = 4 bits.

Therefore:

```
Logical Address = 011001

+----------------+----------------+
| Page Number    | Offset         |
| 01             | 1001           |
+----------------+----------------+
```

Step 2: Find the page number.

```
Page Number = 01 (Binary)
            = 1 (Decimal)
```

So, we need Page 1.

Step 3: Check the page table.

```
Page 0 → Frame 3
Page 1 → Frame 7  ← Selected
Page 2 → Frame 5
Page 3 → Frame 2
```

Therefore:

```
Page 1 → Frame 7
```

Step 4: Calculate physical address.

Frame size = 16 bytes.

Frame 7 starts at:

7 x 16 = 112

Offset = 9 (because 1001 in binary = 9).

Therefore:

Physical Address = Frame Base + Offset = 112 + 9 = 121

### Complete Address Translation Diagram

```
       CPU
        |
        | Logical Address = 25
        | Binary = 011001
        v
   +------------------+
   | Page No | Offset |
   |   01    |  1001  |
   +------------------+
        |
        | Page Number = 1
        v
   +------------------+
   |    PAGE TABLE    |
   +------------------+
   | Page 0 → Frame 3 |
   | Page 1 → Frame 7 |
   | Page 2 → Frame 5 |
   | Page 3 → Frame 2 |
   +------------------+
        |
        | Frame Number = 7
        v
   +------------------+
   | Frame Base = 112 |
   | Offset    = 9    |
   +------------------+
        |
        v
   Physical Address
    112 + 9 = 121
        |
        v
      MAIN RAM
```

Remember: Page number changes into a frame number during translation. Offset remains the same.

## 6. How Does Paging Avoid External Fragmentation?

In contiguous allocation, a process requires one continuous block of memory.

In paging, a process is divided into smaller pages, and these pages can be stored in any available free frames.

Example:

Suppose physical memory has the following free frames:

```
+------------------+
| Process P1       |
+------------------+
| Free Frame       |
+------------------+
| Process P2       |
+------------------+
| Free Frame       |
+------------------+
```

A process P3 requires 2 KB, and each page is 1 KB.

We can allocate:

```
P3 Page 0 → First Free Frame
P3 Page 1 → Second Free Frame
```

Even though the free frames are not adjacent, the process can still be loaded.

Conclusion: Paging avoids external fragmentation because pages can occupy non-contiguous free frames.

## 7. Why Is Paging Slow?

You might wonder:

If paging solves external fragmentation, what is its disadvantage?

The main issue is additional memory references during address translation.

Why?

Because the page table itself is stored in main memory (RAM).

Suppose the CPU wants to access some data.

It needs:

1. First memory access: Access the page table to find the frame number.
2. Second memory access: Access the actual data from physical memory.

Diagram:

```
           CPU
            |
            v
       Logical Address
            |
            v
       +-----------+
       | Page Table|
       |  (RAM)    |
       +-----------+
            |
            | Get Frame Number
            v
       Physical Address
            |
            v
       +-----------+
       | Actual    |
       | Data (RAM)|
       +-----------+
```

Therefore, two memory accesses may be required for one data access.

Solution: Translation Look-aside Buffer (TLB).

## 8. Translation Look-aside Buffer (TLB)

TLB is a hardware-supported, high-speed memory cache used to speed up paging.

It stores recently used page-to-frame mappings.

Instead of accessing the page table in RAM every time, the CPU first checks the TLB.

### How Does TLB Work?

Suppose we want to access Page 1.

Case 1: TLB Hit

A TLB hit occurs when the requested page-to-frame mapping is already available in the TLB.

Example:

```
           CPU
            |
            v
       Logical Address
            |
            v
       +-----------+
       |    TLB    |
       +-----------+
            |
            | Page 1 found
            v
       Frame 7
            |
            v
       Physical Memory
```

The frame number is obtained directly from the TLB.

No page table lookup is required for this translation.

Case 2: TLB Miss

A TLB miss occurs when the requested mapping is not available in the TLB.

Example:

```
           CPU
            |
            v
       Logical Address
            |
            v
       +-----------+
       |    TLB    |
       +-----------+
            |
            | Page 1 not found
            v
        TLB MISS
            |
            v
       +-----------+
       | Page Table|
       |   (RAM)   |
       +-----------+
            |
            | Find Frame Number
            v
       Update TLB
            |
            v
       Physical Memory
```

The system accesses the page table in RAM, finds the corresponding frame number and stores the mapping in the TLB.

Next time, the mapping can be obtained directly from the TLB.

Important: A TLB miss does not mean that the requested page is absent from RAM. It only means that the mapping is not present in the TLB.

## 9. TLB Structure: Key and Value

TLB works like a cache containing key-value pairs.

Example:

| Key (Page Number) | Value (Frame Number) |
| ----------------- | -------------------- |
| Page 0            | Frame 3              |
| Page 1            | Frame 7              |
| Page 2            | Frame 5              |
| Page 3            | Frame 2              |

When a page number is requested, TLB searches for the corresponding frame number.

```
       TLB
  +-------------+-------------+
  |     KEY     |    VALUE    |
  +-------------+-------------+
  |   Page 0    |   Frame 3   |
  +-------------+-------------+
  |   Page 1    |   Frame 7   |
  +-------------+-------------+
  |   Page 2    |   Frame 5   |
  +-------------+-------------+
  |   Page 3    |   Frame 2   |
  +-------------+-------------+
```

## 10. ASID (Address Space Identifier)

Problem: What happens when multiple processes use the same TLB?

Different processes can have the same logical page number but map it to different physical frames.

Example:

```
Process P1:
Page 0 → Frame 3

Process P2:
Page 0 → Frame 7
```

Both processes have Page 0, but their physical mappings are different.

How does TLB identify which process a mapping belongs to?

Solution: ASID (Address Space Identifier).

ASID is a unique identifier associated with a process's address space.

Each TLB entry stores an ASID along with its page-to-frame mapping.

Example:

| ASID | Page Number | Frame Number |
| ---- | ----------- | ------------ |
| 10   | 0           | 3            |
| 20   | 0           | 7            |
| 10   | 1           | 5            |
| 20   | 1           | 2            |

Now TLB can distinguish between mappings belonging to different processes.

### How Does ASID Work?

1. Every process has a unique ASID.
2. TLB entries store the ASID.
3. When a process requests an address, TLB checks the page mapping and ASID.
4. If the ASID matches the currently executing process, the mapping can be used.
5. If the ASID does not match, it is treated as a TLB miss.

### TLB and Context Switching

When a context switch occurs, the active process changes.

We can also reset TLB contents during a context switch. But this flushing removes useful cached mappings, causing additional page-table lookups and performance overhead.

So ASIDs allow entries belonging to multiple processes to coexist in the TLB, avoiding confusion between their address spaces.

## 11. Fixed Partitioning vs Dynamic Partitioning vs Paging

| Basis                  | Fixed                | Dynamic            | Paging           |
| ---------------------- | -------------------- | ------------------ | ---------------- |
| Allocation             | Contiguous           | Contiguous         | Non-contiguous   |
| Memory division        | Fixed partitions     | Runtime partitions | Pages and frames |
| Internal fragmentation | Yes                  | No (basic model)   | Possible         |
| External fragmentation | Possible             | Yes                | No               |
| Compaction             | Not generally needed | May be needed      | Not needed       |
| Page table             | No                   | No                 | Yes              |

Note: Paging can have internal fragmentation, usually in the last page of a process.
